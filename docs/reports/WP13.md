## Built (against the brief, page by page)
- **Renderer**, `src/shared/printouts/` (`index.js`, `browser.js`; documented at the top of each): `renderPdf('<template>', data, { landscape })` returns a Buffer. Handlebars with D4's partials and helpers; one shared Chromium started on first use, kept open while busy, closed after `PDF_BROWSER_IDLE_MS` idle, restarted after `PDF_BROWSER_MAX_PAGES` pages and after a crash (one retry); a pool of `PDF_TAB_POOL_SIZE` tabs, the rest wait; waits for fonts; a timeout on every render and a hard stop; a limit on the HTML size; errors logged and returned as a plain message (never left hanging). Render options: A4, `preferCSSPageSize`, `printBackground`, `displayHeaderFooter` with the footer partial as the footer template and an empty header, tagged PDF. Settings are `PDF_*` in `.env`, read by `src/config/index.js`.
- **No internet at render time**: the page is loaded with a `<base>` on a made-up origin and every request is answered from the app's disk by request interception (the templates folder, and the crest from `public/assets/navy-logo.png`); any other request is refused. Fonts (Inter, Libre Baskerville) are D4's local files.
- **Chromium path** is a setting, `PDF_CHROMIUM_PATH`; empty uses the binary inside `@sparticuz/chromium` (as NAVY-PAYROLL does). Both ways were rendered in this container (Playwright's at `/opt/pw-browsers`, and the `@sparticuz` one).
- **Templates** moved to `src/templates/printouts/`: all 27 `.hbs`, `partials/`, `printout.css`, `helpers.js`, `fonts/` (the crest is not copied: it is the app's own `public/assets/navy-logo.png`). `docs/design/` is untouched. Only the helper `datetime` changed: it now writes `dd/mm/yyyy hh:mm` in Nigerian time (WAT, Africa/Lagos, no "UTC"); a string without a zone is taken as UTC.
- **Every PDF the app made is rebuilt** from its template, same routes and file names, still opening in the app's preview: Personnel Dossier (`ratings.printouts.js`, `personnel-dossier`, passport photo as a data URI), one tab of a rating's record (`rating-report`), the ratings list export (`ratings-list`, current and former), the 16 Static Tables lists (`static-table-list` from `tables.service.js`, landscape over four columns, Active last), and the three Disciplinary printouts (`disciplinary.documents.js`: `disciplinary-pending-cases`, `disciplinary-report`, `disciplinary-case-sheet`). "Generated by" is now the signed-in person's name (`req.user.fullName`), as D4 designed, not the user name.
- **Removed**: `src/shared/pdf.js` and the `pdfkit` package. The Excel code is untouched.
- **Packages added, pinned exactly**: `handlebars` 4.7.10, `puppeteer-core` 25.18.1, `@sparticuz/chromium` 153.0.0. The install was allowed.
- **Docs**: `README.md` (section 7: what the server needs for Chromium, the settings, which template makes which printout; tech-stack row; the walkthrough list), `.env.example` (the `PDF_*` settings), `Dockerfile` (installs Alpine's `chromium` and `ttf-liberation` and sets `PDF_CHROMIUM_PATH`), `CONVENTIONS.md` (libraries, folder layout, and "To add a printout" in Frontend, eight steps).
- **Walkthrough steps fixed** (WP3b, WP3c): system admin: Add Account, Manage Password and the Audit Trail's record filter now use the rating search select; disciplinary: Initiate Incident (picking a rating opens its dialog), the Pending and Concluded rating filters, and the API checks that passed `?q=`. The access walkthrough gained a section that opens the dossier, a tab and the nominal roll in the preview and downloads the roll's PDF. No step needed changing for "N/A" or the Details tab's cards.
- **A real bug found and fixed** (shared UI file, one line): in `public/js/ui/rating-search.js` the text field's own `change` event (fired on blur) bubbled up as if a rating had been chosen. On Manage Password, clicking Reset Password after picking a rating blurred the field, the page re-fetched the account and hid the result under the click, so the first click did nothing. The text field's `change` is now stopped at the field; the picker's own `change` (a rating chosen or cleared) is unchanged.

## Decisions taken where the brief and the design were silent
- A render needing more than `PDF_MAX_HTML_MB` (default 10) is refused with a 400 asking for a narrower list; Static Tables still cap at 5,000 rows.
- The nominal roll's summary strip shows Ratings, Ships and Commands (distinct, current list) as D4's sample did; the former list shows Ratings only.
- The Static Tables page's heading is the table's title in capitals; the facts row shows List, Search and Status; "Printed" in the subtitle is today in Nigerian time.
- The rating's other tabs (Advancement, Training, Education) use `rating-report` with their own columns, as D4 said; a drafting row with no end date prints "Present".
- Corrections on the case sheet show the date as the app writes it (the stored value is a timestamp) and the change as "Field: from to to".
- Chromium runs with `--no-sandbox` when a system Chromium is used (the app's own container user is not root; the sandbox needs privileges many hosts do not give); the PDF pages are only ever our own template HTML with every outside request refused.

## For the next packages
- To add a printout, follow "To add a printout" in `CONVENTIONS.md` (Frontend): the template is already in `src/templates/printouts/`; write the data builder in your module, call `renderPdf('<template>', data)`, set `generatedBy` to `req.user.fullName`, and check in your walkthrough that it opens in the preview with pages. The data shape of each template is its `.sample.json` in `docs/design/printouts/`.
- Pass dates as ISO strings (`kind: 'date'` writes `dd/mm/yyyy`); a JavaScript `Date` is not a date to a column of kind `date`, so format it first (the Case Sheet's corrections did this).
- A photo must be a data URI; any other file the template links must sit in `src/templates/printouts/`.
- Do not change the shared CSS or partials without the owner: they are the approved look.
- The rating search select now reports a choice only through its own `change` event. Do not listen for native `change` on its inner text field.
- In a walkthrough: pick a rating with `getByRole('combobox', { name: <label> }).fill(text)`, then click `[role="listbox"] [data-rating="<number>"]` (the list is drawn in `body`, not inside the dialog); "No ratings found" is the empty message; lists filter on one chosen rating, not on typed text.
